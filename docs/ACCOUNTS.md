# Аккаунты и облачные сохранения

Обновлено 2026-10-09.

## Как это работает для игрока

- **Сначала гость.** Игра открывается сразу, без регистрации. Партия, лучшее время, пройденное обучение и настройки звука хранятся на устройстве (`localStorage`).
- **Вход по желанию:** «Пауза → Аккаунт и сохранения → Войти через Google». Одно нажатие, без паролей и форм.
- **После входа** прогресс уходит в облако: не чаще раза в минуту во время игры и сразу, когда игрок сворачивает вкладку или закрывает игру. При запуске и при возвращении на вкладку игра сверяется с облаком.
- **Кто главнее:** побеждает устройство, где играли позже. Лучшее время берётся меньшее из двух, обучение считается пройденным, если пройдено где-то.
- **Две разные партии:** если при первом входе на устройстве (или посреди игры) в облаке оказалась другая партия, игра не выбирает молча, а спрашивает «Какую продолжить?». Заменённая партия на всякий случай остаётся на устройстве (`partshift.account.replacedRun`).
- Без настроенного Firebase (`src/account/config.ts` = `null`) игра работает как раньше, а панель пишет, что облачные сохранения скоро появятся.

## Почему Firebase

| | Firebase (выбран) | Supabase | Свой сервер (Colyseus) |
|---|---|---|---|
| Вход через Google | готовый | готовый | писать самим |
| Бесплатно | тариф Spark без карты | бесплатный проект засыпает через неделю без активности | хостинг ~5 $/мес |
| Android (Capacitor) | официальный плагин `@capacitor-firebase/authentication` | есть | писать самим |

**Цена:** тариф Spark бесплатный и не просит карту. Лимиты Firestore: 1 ГБ данных, 50 000 чтений и 20 000 записей в сутки. Одна запись в минуту активной игры даёт около 300 часов игры в сутки бесплатно; дальше тариф Blaze стоит порядка 0,18 $ за 100 000 записей. Когда появится онлайн на Colyseus, сервер сможет проверять тот же вход Firebase (ID-токен) и знать игрока по его `uid`.

Гости в Firebase не создаются: SDK Firebase (около 80 КБ в gzip) скачивается только после первого входа, поэтому гость не делает ни одного сетевого запроса.

## Устройство кода

- `src/account/snapshot.ts`: что синхронизируется (все ключи `partshift.*`, кроме служебных `partshift.account.*`) и как сливаются две стороны. Новые сохраняемые вещи (просмотренный комикс, настройки) синхронизируются сами, если их ключ начинается с `partshift.`. Тесты: `tests/account.test.ts`.
- `src/account/cloud.ts`: вход, загрузка и выгрузка (`users/{uid}` в Firestore: `blob` со всеми ключами, `changedAt`, `name`).
- `src/account/panel.ts`: окно аккаунта поверх игры (HTML, стиль BRAND_UI). Любое меню открывает его через `openAccountPanel()`.
- `src/main.ts`: `account.boot()` до старта сцены (ждёт облако не дольше 2,5 с).
- `firestore.rules`: каждый игрок читает и пишет только свой документ.

## Что сделать Антону (один раз, ~10 минут)

1. Открыть https://console.firebase.google.com под своим Google-аккаунтом → «Создать проект» → имя `part-shift` → Google Analytics можно выключить.
2. Слева «Build → Authentication» → «Get started» → вкладка «Sign-in method» → «Google» → включить, выбрать почту поддержки → «Save».
3. Там же вкладка «Settings» → «Authorized domains» → «Add domain» → `tatonoma911.github.io`.
4. «Build → Firestore Database» → «Create database» → регион `eur3 (europe-west)` → «Production mode». Потом вкладка «Rules» → вставить содержимое `firestore.rules` из репозитория → «Publish».
5. Шестерёнка → «Project settings» → внизу «Your apps» → значок `</>` → имя `part-shift-web` → «Register app». Скопировать блок `firebaseConfig` и прислать в тред «Аккаунты и сохранения». Эти значения не секретные, они и так видны в коде любой веб-игры на Firebase.

После этого конфиг вставляется в `src/account/config.ts`, и вход заработает на https://tatonoma911.github.io/part-shift/. В превью внутри claude.ai вход работать не будет (там нельзя открыть окно Google), это нормально.
