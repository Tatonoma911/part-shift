# Итоги, досье и тайник: решения доработки

Дата: 2026-10-11. Опирается на `design/INTERFACE_SYSTEM.md` (ветка `claude/project-thread-fp1zl5`): токены, кнопки, шкала текста.

## Что сделано

1. **Одна система кнопок.** В `src/game/meta/kit.ts` появилась константа `BTN`: `sm` 96, `md` 112, `lg` 128 логических px. На телефоне сцена рисуется в 2×, значит это 48, 56 и 64 css px. `button()` больше не делает кнопок ниже 96 (минимальная цель касания 48 css px). Прежние высоты 70, 80 и 84 (42 css px) были ниже минимума.
2. **Итоги смены** (`ResultsScreen.ts`):
   - главная кнопка `lg`, «Досье» и «Меню» `sm`, дополнительные кнопки `sm`;
   - заголовок победы и поражения на размере display (28 css px), подпись на 14 css px;
   - заголовок и подпись разведены по вертикали, подпись не наезжает на заголовок;
   - карточка возвращённого героя: «Взять» `md`, «Понятно» `sm`.
3. **Досье** (`DossierScene.ts`): кнопки «Назад» и «Демо» `sm` у верхнего края, кнопки в листе героя `md` и `sm`.
4. **Тайник** (`BoonPick.ts`):
   - текст описания с 11 css px до 15 css px (минимум для чтения, `t-body`);
   - имя 16 css px (`t-h2`), подпись капсом 13 css px, строка «Звонок» 12 css px;
   - карточка на телефоне выше (300 вместо 262), чтобы описание помещалось; таймер считает от высоты карточки.

## Решения, которые принял без Антона

- Высоты кнопок берутся из трёх значений `BTN`, а не из чисел в каждом экране. Новый экран берёт размер отсюда.
- Цвет и форма в этих экранах не менялись: значки ✓ ◆ ▲ остаются там, где были.
- Картинки героев и победы не трогались: по `design/INTERFACE_SYSTEM.md` они остаются за Художником и Аниматором.
- Экран поражения проверен кодом (тот же путь, что победа, другой цвет и заголовок). В превью `?meta=results` поражение не открывается отдельно; проверить вручную на устройстве.

## Проверка

- `tsc --noEmit`: без ошибок.
- `vitest`: `meta.test.ts`, `i18n.test.ts`, 11 тестов проходят.
- Скриншоты телефон 390 × 844 и ПК 1280 × 720 (в превью для Антона, не в репозитории).
- Контраст и тексты: проверены вручную по `design/INTERFACE_SYSTEM.md` §3.2 и правилам кнопок. Полные прогоны `design-critique`, `accessibility-audit` и `ux-writing` в этой итерации не запускались; это открыто и указано в отчёте.
